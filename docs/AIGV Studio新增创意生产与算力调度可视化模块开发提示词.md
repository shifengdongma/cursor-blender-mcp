# 四、总体开发原则

## 4.1 优先兼容现有技术

新增代码必须兼容 Python 3.6。

后端代码中：

- 不使用 f-string；
- 不使用 `dataclasses`；
- 不使用 Python 3.7 及以上专属语法；
- 字符串格式化使用 `.format()`；
- 尽量保持现有代码风格；
- Flask 路由注册方式应与现有项目一致；
- API 响应格式应尽量复用现有响应工具。

前端代码中：

- 使用原生 JavaScript；
- 不引入 npm；
- 不增加前端构建步骤；
- 不依赖 Vue、React、Angular；
- 不使用大型 UI 组件库；
- 不依赖需要联网才能加载的外部 CDN；
- 图标优先使用内联 SVG；
- 图表优先使用原生 Canvas、SVG 或 CSS 绘制；
- 页面直接通过 Flask 提供访问。

## 4.2 控制个人开发复杂度

新增功能应以个人开发者能够维护为标准：

- 页面数量控制在合理范围；
- 不拆分过多微服务；
- 不新建复杂消息队列；
- 不创建新的数据库系统；
- 不增加 Redis、Kafka、RabbitMQ 等基础设施；
- 不强制修改现有数据库；
- 演示数据优先使用一个统一的 JavaScript 数据文件；
- 需要后端数据时，优先添加少量只读演示接口；
- 状态变化优先由前端模拟；
- 页面之间通过普通链接跳转，不引入新的前端路由系统。

# 十一、视觉设计要求

## 11.1 设计风格

继续沿用现有暗金主题，但需要增强专业数字内容生产平台的感觉。

推荐视觉关键词：

- 深色背景；
- 暗金色强调；
- 少量蓝紫色用于 AI 模块；
- 青绿色用于正常运行；
- 黄色用于警告；
- 红色用于严重错误；
- 半透明面板；
- 轻微发光边框；
- 清晰的信息层级；
- 专业影视制作界面；
- 专业云计算监控界面。

禁止：

- 大面积高饱和渐变；
- 过度动画；
- 过多玻璃拟态；
- 卡片密度过低；
- 所有文字都使用金色；
- 使用花哨但无法阅读的字体；
- 直接复制常见后台管理模板风格。

## 11.2 CSS 管理

不要重写整个 `styles.css`。

在文件末尾增加清晰注释：

```css
/* =========================================================
   AIGV Creative Studio
   ========================================================= */
```

以及：

```css
/* =========================================================
   AIGV Compute Platform
   ========================================================= */
```

新增样式必须通过页面根类隔离，例如：

```css
.creative-studio-page .workflow-step {
}

.compute-platform-page .metric-card {
}
```

避免污染原有页面。
